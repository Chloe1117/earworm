## 1. Critical Review — K-pop 전환이 깨뜨리는 것과 새로 생기는 리스크

> 💡 **Critical Insight**: K-pop 은 수요를 크게 키우지만 이전 계획의 전제 세 가지를 무너뜨린다.
> ① 구매자가 한국 밖에 있으므로 **한국 유료 차트 목표가 무효**가 된다.
> ② 초보자는 한글 가사를 직접 입력할 수 없으므로 **"가사는 사용자가 입력" 구조가 작동하지 않는다.**
> ③ 가수 이름을 스토어 등록정보에 쓸 수 없으므로 **가장 강한 검색 키워드가 막힌다.**

| # | 병목 | 왜 치명적인가 | 대응 |
| :-- | :-- | :-- | :-- |
| 1 | **시장이 해외로 이동** | 한국 사용자는 한국어를 배울 필요가 없다. 국가마다 차트 경쟁 강도와 결제 의향이 다르다 | 대상 국가를 1~2개로 좁히고 실측으로 고른다 (3장) |
| 2 | **가사 입력 장벽 → 저작권 노출** | 가치의 핵심인 "가사 + 로마자 + 번역 + 단어 풀이"를 앱이 제공하면 음악 출판사 라이선스 영역 | 사용자가 가사를 **붙여넣고**, 앱은 **기기 안에서만** 분석한다. 서버 저장·공유·앱 내장 금지. 여전히 회색 지대이므로 출시 전 법률 검토 |
| 3 | **아티스트 IP** | HYBE·SM·JYP·YG 는 IP 대응이 강하다. 앱 이름·아이콘·스크린샷에 그룹명이나 멤버 사진을 쓰면 Play 의 지식재산권 정책 위반으로 삭제될 위험 | 기능 키워드로만 노출: *K-pop sing-along · Korean lyrics · romanization · pronunciation*. 곡명은 사용자 리뷰·커뮤니티가 대신 퍼뜨리게 한다 |
| 4 | **YouTube 정책** | YouTube API 정책은 YouTube 콘텐츠 자체에 요금을 매기는 것을 금한다 | **도구**(루퍼·발음 분해·7일 루틴)를 판다. 스토어 문구에 "뮤직비디오 무제한" 같은 콘텐츠 판매 표현 금지 |
| 5 | **결제 능력** | 해외 K-pop 팬은 10대 비중이 높아 카드가 없는 경우가 많다 **[추정]** | 선결제 vs 무료+1회 해금을 **대기자 응답 데이터로 결정** (4장 가격 규칙) |
| 6 | **공식·대형 경쟁자** | HYBE 공식 "Learn! KOREAN with BTS", Duolingo·LingoDeer·TTMIK, 팬 가사 번역 사이트 | 문법 강의로 싸우지 않는다. **"오늘 후렴 한 줄을 입에 붙이기"** — 발음·리듬·반복에 집중 |
| 7 | **LLM 원가 vs 1회 결제** | 단어 풀이를 LLM 으로 만들면 호출마다 비용이 드는데 수익은 1회뿐 | 로마자·음운 변화는 **규칙 기반(무료, 기기 안)**. LLM 은 줄 단위 요청 시에만, 기기 캐시, 1인당 일일 한도 |

### 포지셔닝 결론

K-pop 가사는 영어 혼용·속어·반말·생략이 많아 **문법 교재로는 나쁘다**. 팬이 원하는 것은 문법이 아니라 **따라 부르고, 무슨 뜻인지 아는 것**이다.

→ "K-pop 으로 한국어 배우기"가 아니라 **"K-pop 따라 부르기 트레이너"**.
기존 코드의 A-B 구간반복 · 0.75x 재생 · 녹음 비교 · 7일 루틴이 이 용도에 거의 그대로 맞는다.

## 4. 가격 · 수익 모델

"유료 인기 1위"라는 원래 목표는 **선결제 앱**이어야 성립한다. 하지만 해외 10대 팬에게 선결제는 진입 장벽이다. 둘 중 하나를 감으로 고르지 않고 **Phase 0 응답으로 정한다.**

| 조건 (대상 국가 대기자 기준) | 모델 | 목표 차트 |
| :-- | :-- | :-- |
| 지불 의향 중앙값 ≥ **US$2.99** | **선결제 유료 앱** (현지 가격 자동 환산) | 해당 국가 유료 인기 |
| 중앙값 < US$2.99 | **무료 + 1회 해금**(곡 슬롯 무제한 · 발음 분해) — Play Billing | 무료 인기 → 매출 최고(교육) |

> ⚠️ Play 에서 **유료 → 무료 전환은 가능하지만 무료 → 유료는 불가**하다. 확신이 없으면 무료 + 1회 해금이 되돌릴 수 있는 선택이다.

## 6. 10X Critical Action

* **[Action 1] 지금 당장 — 가짜 문 테스트(fake-door test).** 랜딩 페이지 1장 + 숏폼 1편으로 시작한다. **7일 안에 대기자 100명**이 모이면 개발, 못 모이면 코드 한 줄 쓰기 전에 방향을 바꾼다.

* **[Action 2] 장기 축적 — Supabase 스키마.** 국가 · 가격 · 곡을 수요 데이터가 결정하게 만든다.

```sql
-- Phase 0: 수요 검증
create table waitlist (
  id           uuid primary key default gen_random_uuid(),
  country      text not null,
  bias_group   text,          -- 최애 그룹 (팬덤 용어)
  song_request text,          -- 처음 배우고 싶은 곡
  price_ok_usd numeric,       -- 낼 수 있다고 답한 최고 가격 → 4장 가격 규칙 입력값
  src          text,          -- tiktok | reels | community
  created_at   timestamptz default now()
);

-- 출시 후: 국가별 일일 차트·매출 (Play Console 내보내기 적재)
create table play_daily (
  d          date not null,
  country    text not null,
  paid_rank  int,
  edu_rank   int,
  installs   int,
  purchases  int,
  refunds    int,
  price_usd  numeric,
  primary key (d, country)
);

-- 학습 행동 (옵트인 · 익명) — 어느 곡·어느 날에 이탈하는가
create table song_session (
  id          uuid primary key default gen_random_uuid(),
  device_hash text not null,
  video_id    text not null,
  day_idx     smallint,       -- D1..D7
  loops       int,            -- A-B 반복 횟수
  seconds     int,
  completed   boolean,
  created_at  timestamptz default now()
);
```

> ⚠️ `song_session` 은 개인정보 처리방침과 Play **데이터 보안** 섹션 신고 대상이다. README 의 "개인 데이터는 localStorage 에만" 원칙과 충돌하므로 **옵트인 + 익명 해시**로만 도입한다. **가사 원문은 어떤 테이블에도 저장하지 않는다.**
