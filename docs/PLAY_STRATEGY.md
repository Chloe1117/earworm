> 전제: 이 저장소의 `index.html`(Girl on Fire 7일 파일럿)을 **Earworm** 이라는 유료 안드로이드 앱으로 내보낸다.

## 1. Critical Review — "유료 매출 1위 앱을 만들어줘"의 허점

> 💡 **Critical Insight**: 코드는 순위를 만들지 못한다. 순위는 **출시 첫 72시간의 결제 속도**가 만든다. 그리고 지금 제품에는 아래 5개의 구조적 병목이 있다.

| # | 병목 | 왜 치명적인가 | 대응 |
| :-- | :-- | :-- | :-- |
| 1 | **"유료 1위"의 정의가 모호** | '유료 인기(Top Paid)'는 **결제 건수**, '매출 최고(Top Grossing)'는 **금액**. 매출 최고는 IAP 게임이 독식하므로 1인 개발 교육 앱에겐 사실상 불가능 | 목표를 **한국 · 유료 인기 · 교육 카테고리 1위 → 전체 유료 인기 Top 10** 으로 좁힌다 |
| 2 | **TWA = 공개 웹사이트** | 앱 본체가 GitHub Pages 에 공개돼 있으면 URL만 알면 무료. 유료 앱의 가치가 새어나간다 | v1은 감수(Play 사용자 대부분은 URL을 찾지 않는다). 판매가 확인되면 v2에서 곡 팩을 **Digital Goods API + Play Billing** 뒤로 잠근다 |
| 3 | **YouTube · 가사 저작권** | YouTube API 정책은 YouTube 콘텐츠 자체에 요금을 매기는 것을 금한다. 가사 원문을 앱이 내장·배포하면 음악 출판사 라이선스 영역 | **"도구"를 판다**: A-B 루퍼·7일 루틴·카드 시스템. 가사는 **사용자가 직접 입력**(현 구조 유지). 스토어 설명·스크린샷에 곡명·아티스트 로고 사용 금지 |
| 4 | **Play 개인 개발자 계정 게이트** | 신규 개인 계정은 프로덕션 출시 전 **비공개 테스트(테스터 12명 × 14일 연속)** 를 통과해야 한다 [출시 시점 정책 재확인] | 이 14일을 **런치 대기자 모집 기간**으로 겸한다. 테스터 = 첫날 구매자 후보 |
| 5 | **현 코드는 1곡 하드코딩** | `DAYS`·`SECS`·참고 탭이 Girl on Fire 전용. 이대로 팔면 환불·별점 테러 | 출시 전 필수: **곡 슬롯 N개**(사용자가 URL+가사 입력) + 루틴 템플릿 일반화 |

## 2. Key Summary

* **Core Objective**: "노래 한 곡을 7일 만에 입에 붙이는 영어 루틴 도구"를 **₩3,900 일회성 구매**로 팔아, 한국 유료 인기 차트의 **낮은 진입 임계치**를 출시 첫 주에 집중 돌파한다.
* **Strategic Impact**: 유료 차트는 무료 차트보다 경쟁 볼륨이 한두 자릿수 작다 **[추정]**. 하루 수백 건 수준의 결제를 **동시에** 몰면 차트 진입 → 차트 노출 자체가 유기 유입을 만드는 **플라이휠**이 돈다. 광고비가 아니라 **타이밍 설계**가 레버리지다.

## 4. 10X Critical Action

* **[Action 1] 지금 당장 — 계측부터 심는다.** 차트 순위는 사후에 원인 분석이 안 된다. 출시 전 Play Console 의 **획득 보고서 · 스토어 등록정보 실험(A/B)** 을 켜고, 앱 내에는 `?src=twa|pwa` 로 유입 경로를 구분(이미 `start_url` 에 반영). 아이콘·첫 스크린샷 2종 A/B 는 런치 **전** 비공개 테스트 기간에 끝낸다.

* **[Action 2] 장기 축적 — Supabase 스키마.** 순위 · 결제 · 학습 행동을 한 테이블 축에서 조인해야 "어떤 곡이 결제를 만드는가"가 보인다.

```sql
-- 일별 차트/매출 스냅샷 (Play Console 내보내기 → 수동/자동 적재)
create table play_daily (
  d            date primary key,
  paid_rank_kr int,          -- 유료 인기 전체 순위
  edu_rank_kr  int,          -- 교육 카테고리 순위
  installs     int,
  purchases    int,
  refunds      int,
  price_krw    int,
  store_cvr    numeric       -- 스토어 방문 → 구매 전환율
);

-- 학습 행동 (옵트인, 익명) — 어떤 곡·단계에서 이탈하는가
create table song_session (
  id          uuid primary key default gen_random_uuid(),
  device_hash text not null,
  video_id    text not null,
  day_idx     smallint,      -- D1..D7
  loops       int,           -- A-B 반복 횟수
  seconds     int,
  completed   boolean,
  created_at  timestamptz default now()
);
```

> ⚠️ `song_session` 은 개인정보 처리방침 · Play **데이터 보안** 섹션 신고 대상이다. 현재 README 의 "개인 데이터는 localStorage 에만" 원칙과 충돌하므로 **옵트인 + 익명 해시**로만 도입한다.
